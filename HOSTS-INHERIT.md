# Входящий → Host: живое наследование fingerprint и ALPN

Направление: **администратор сохраняет значения во входящем, связанные Hosts
получают их автоматически**. Без общего `apply`, `init-config` и перезапуска
панели или Xray. Это отдельный нативный systemd-worker с Python 3, а не
возвращение массовой legacy-синхронизации Hosts. Интервал — примерно секунда.

## Точные правила

- Fingerprint читается из `tlsSettings.settings.fingerprint` или
  `realitySettings.settings.fingerprint`; если вложенного нет — из fingerprint
  самого TLS/REALITY-блока.
- ALPN читается из `tlsSettings.alpn`/`realitySettings.alpn`, затем из
  `settings.alpn`, если верхнего поля нет.
- Отсутствующее поле означает **сохранить Host**. Явно пустые `""`/`[]` означают
  очистить соответствующее наследуемое поле.
- Никаких догадок Firefox/Chrome, h2/http/1.1 по умолчанию или по протоколу.
- Меняются только fingerprint, ALPN и timestamp изменённой строки. Адрес, порт,
  SNI, security, path, включённость, входящие, клиенты и ключи не меняются.
- Выбираются существующие включённые Hosts включённых входящих с совместимой
  защитой: та же TLS/REALITY либо `same`/пустое значение в Host.
- У XHTTP-backend с `security=none` нет собственного TLS-профиля. Его внешний
  TLS Host пропускается, ручные поля сохраняются.

Некоторые версии панели не дают задавать ALPN для REALITY во входящем. Worker
не добавляет поле UI и не придумывает значение: ALPN Host в этом случае
сохраняется. Настройки клиента не являются «отпечатком сервера».

## Включение без перезапуска работающего Xray

Сохраните текущую БД и активный `.env`, получите обновление:

```bash
x-ui-fork backup
git pull --ff-only
```

В **серверном** окружении:

```dotenv
XUI_HOSTS_INHERIT_TLS=true
XUI_HOSTS_SYNC=false
XUI_AUTO_DB_APPLY=false
```

Последние два флага включать для наследования не нужно: это другая, полная
перенастройка с потенциальными перезапусками.

Для первой проверки ограничьте список **ID Hosts, не ID входящих**:

```dotenv
# Пример: замените реальным ID нужного Host.
XUI_HOSTS_INHERIT_TLS_HOST_IDS=45
```

Пустой список означает все совместимые активные Hosts. Ручные исключения имеют
приоритет:

```dotenv
XUI_HOSTS_INHERIT_TLS_EXCLUDE=100
```

Задайте нужный fingerprint/ALPN во входящем и сначала посмотрите план:

```bash
x-ui-fork hosts-inherit plan
```

План не изменяет БД/службы; показывает ID Host, ID входящего и отличающиеся поля.
После проверки запустите **отдельный** worker:

```bash
x-ui-fork hosts-inherit install
x-ui-fork hosts-inherit status
```

Устанавливается и перезапускается только `x-ui-hosts-tls-inherit.service`.
Эта команда не вызывает общий `apply/restart`, `init-config`, не перезапускает
x-ui, Xray, Nginx или HAProxy. Устанавливать всю обвязку через `apply` для этого
сценария не требуется: CLI запускает обновлённый помощник из проекта.
Сама панель может штатно применять/перезагружать свой Xray-конфиг при сохранении
входящего; worker не добавляет к этому ни общего применения, ни своего restart.

После сохранения входящего выбранные Hosts обновляются с короткой задержкой.
Обновите список Hosts в браузере и подписку на клиенте. Уже импортированные
клиентские профили сами не переписываются. Worker обновляет БД, а не внутренний
кеш сторонней версии панели: выдачу подписки необходимо проверить на своей
версии; если она кеширует Hosts, нужна поддержка её API, а не скрытый restart.

## Исключения, однократное применение и отключение

- `x-ui-fork hosts-inherit once` — однократно изменить только эти поля.
- Ручное изменение наследуемого поля Host заменится источником на следующем
  проходе. Для ручного Host добавьте ID в EXCLUDE или уберите из HOST_IDS.
- После изменения разрешения/списков выполните `hosts-inherit install`:
  новое окружение прочитает только перезапущенный worker.
- Для отключения задайте `XUI_HOSTS_INHERIT_TLS=false` и выполните ту же команду.
  Worker остановится; уже скопированные значения автоматически не откатываются.

Если значения совпадают, UPDATE не выполняется и timestamp не меняется —
синхронизация не порождает циклических записей. Неправильные параметры пропускаются
без печати ключей и stream JSON. При отсутствующем пути новая БД не создаётся.
После восстановления БД worker перечитывает текущий файл. Перед записью источник
повторно проверяется под блокировкой транзакции, чтобы не применить устаревшие
значения после параллельного сохранения формы.
