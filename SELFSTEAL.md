# Нативный REALITY SelfSteal

Это **явно включаемый** режим: REALITY принимает клиентские соединения, а
неавторизованный TLS-трафик передаёт локальному HTTPS-сайту Nginx через Unix-сокет
с PROXY protocol v1. Подход соответствует механизму, показанному в
[пользовательском шаблоне репозитория Remnawave](https://github.com/remnawave/templates/blob/main/by-unknown/xray-core/example-vless-selfsteal-with-nginx.json).
Это не копия всей Remnawave и не гарантия нераспознаваемости ТСПУ.

## Отличия от legacy

| | legacy | reality |
|---|---|---|
| HTTPS-заглушка | Существующая обвязка, возможны HAProxy и публичный Nginx | Только локальный Nginx |
| Основной target | Зависит от входящего | `/run/x-ui-selfsteal/https.sock` |
| PROXY protocol | Зависит от настройки | v1 на Unix-сокете, `xver=1` в REALITY |
| Сертификат | Есть прежние fallback-механизмы | Доверенная цепочка, имя и ключ проверяются; не менее суток до истечения |
| Область применения | Прежние установки | Нативная установка с systemd и x-ui/Xray от root |
| Docker/Python fallback | Прежнее поведение | Не поддерживаются; применение прерывается |
| HTTP-транспорты | Прежняя динамическая выборка | Явный список локальных backend ID, read-only БД |

**Существующие входящие, клиенты, ключи и Hosts не переписываются этим режимом.**
В этом режиме legacy-синхронизация портов/listen/target и Hosts внутри
`sync_haproxy_and_hosts` пропускается, чтобы не перезаписать ручные поля и не
вернуть HTTP-клиентов на 443. Однако обычные `x-ui-fork apply/restart` по-прежнему
выполняют **другие** общие операции настройки панели. Для первой проверки
используйте `x-ui-fork selfsteal plan/apply`, а не массовое применение настроек.

В legacy-режиме автосинхронизация Hosts также выключена по умолчанию
(`XUI_HOSTS_SYNC=false`). Fingerprint и ALPN задаются в Host вручную и не обязаны
совпадать с серверным входящим. Принудительная замена ALPN входящих на
`http/1.1` удалена. Обновление не сбрасывает уже сохранённые значения: если старый
скрипт успел их изменить, восстановите проверенные настройки в панели и обновите
клиентскую подписку. Рабочую комбинацию не следует массово заменять на другую.

Если нужно противоположное — задать эти два поля во входящем и получить их в
Hosts на лету — включите отдельное [живое наследование](HOSTS-INHERIT.md).
Оно доступно в REALITY SelfSteal, не меняет другие поля и не вызывает общий apply
или перезапуск Xray.

## 1. Подготовка

1. Сделайте бэкап БД и активного файла окружения. Сохраните работающий резервный
   профиль и административный доступ. Сам режим не вносит изменений в БД, но
   следующие ручные действия в панели уже меняют её.
2. Выберите **свой** домен, например `edge.example.com`, направленный на узел.
   Не копируйте это демонстрационное имя буквально. Панель лучше отделить и
   ограничить доступ к ней; другое имя на том же IP не скрывает общий адрес.
3. Заранее выпустите доверенный сертификат с полной цепочкой и настройте его
   продление. По умолчанию режим не выпускает сертификат и не подставляет случайный или
   самоподписанный. Nginx не занимает публичный 80: для ACME используйте DNS-01
   либо отдельно организованный HTTP-01. Продление сертификата требует reload
   локального Nginx; обновлённый certbot hook форка отдельно перезагружает
   `x-ui-decoy.service` (его нужно переустановить вместе с обвязкой).
   Для выпуска средствами обвязки требуется `XUI_AUTO_CERTS=true`; без него
   существующий сертификат читается, но автоматический запрос к CA не запускается.
   Разовое явное разрешение без списка доменов: `x-ui-fork selfsteal certificate`.
   Проверяются все обнаруженные SAN; разрешённое согласование выполняется до
   строгой проверки, поэтому добавление второго имени не блокирует сам выпуск.
4. Установите `nginx`, `openssl`, `curl`. Проверьте, что x-ui/Xray запускаются от
   root: каталог сокета имеет права 0700. Непривилегированный Xray в этой версии
   режима не поддерживается. Проверка `nginx -t` также проверит наличие HTTP/2.
5. Проверьте, кто использует публичные порты. Не освобождайте 443 вслепую. Для
   теста можно создать новый REALITY-входящий на свободном другом порту, а на 443
   переносить его только после отдельной проверки и подготовки окна работ.

> Переключение legacy → reality заменяет конфигурацию службы `x-ui-decoy`:
> прежние публичные 80/443 больше не обслуживаются этой службой. HTTP-маршруты
> нужно явно выбрать, как описано ниже; невыбранные маршруты не наследуются.
> Старые клиенты не переключаются автоматически на REALITY-фронтенд. Нельзя
> менять публичную схему рабочего узла без плана миграции. Безопаснее первый
> тест на отдельном узле.

## 2. Окружение узла

В **активном серверном** `.env`, не в примере и не в локальной копии бэкапа:

```dotenv
XUI_HAPROXY_ENABLE=false
XUI_SELFSTEAL_ENABLE=true
XUI_SELFSTEAL_MODE=reality
XUI_SELFSTEAL_PUBLIC=false
XUI_SELFSTEAL_DOMAIN=edge.example.com
XUI_SELFSTEAL_PORT=10444
XUI_SELFSTEAL_TEMPLATE=tech
```

По умолчанию используются:

```text
/etc/letsencrypt/live/edge.example.com/fullchain.pem
/etc/letsencrypt/live/edge.example.com/privkey.pem
```

Если сертификат хранится иначе, задайте `XUI_SELFSTEAL_CERT_FILE` и
`XUI_SELFSTEAL_KEY_FILE`. Поддерживаются абсолютные пути без пробелов и
специальных символов. Имя берётся из serverNames активных локальных
SelfSteal-входящих или явного `XUI_SELFSTEAL_DOMAIN`; домен панели по догадке
не подставляется. Старый `XUI_HAPROXY_ENABLE=true` и публичный Nginx несовместимы
с прямым режимом. Для нескольких профилей на общем внешнем443 есть отдельный
[явно включаемый SNI-router](SNI-ROUTER.md) с локальными входящими.

После установки обновлённой обвязки сначала выполните:

```bash
x-ui-fork selfsteal plan
x-ui-fork selfsteal validate
```

`plan` проверяет параметры, доверие сертификату и соответствие ключа, выводит
поля панели и **не меняет БД/службы**. DNS, свободный внешний порт и доступность
из сетей клиентов проверяются отдельно. `validate` дополнительно проверяет
нативное окружение и права root. Ошибка в новом режиме останавливает
`init-config` ещё до его операций с БД и службами.

## 3. Поднять только локальный backend

```bash
x-ui-fork selfsteal apply
x-ui-fork selfsteal status
```

`apply` проверяет конфигурацию Nginx **до** замены, сохраняет прежние конфигурацию
и unit для отката в случае ошибки запуска/HTTPS-проверки. Служба не слушает
публичные 80/443: только приватный Unix-сокет и совместимый HTTPS на
`127.0.0.1:10444`. Проверка сокета использует PROXY protocol и обычную проверку
TLS, без `curl -k`. При неуспехе запуска или проверки прежняя конфигурация службы
восстанавливается; DB и входящие не затрагиваются. Первая прежняя конфигурация
Nginx также сохраняется как `/etc/x-ui/nginx-decoy.conf.pre-reality`.

## 4. Создать НОВЫЙ тестовый входящий в панели

Не переделывайте существующий профиль с чужим SNI.

| Поле | Значение |
|---|---|
| Протокол | VLESS |
| Транспорт | TCP / RAW — название зависит от версии панели |
| Защита | REALITY |
| Listen | `0.0.0.0` |
| Порт | Свободный тестовый; 443 только если он свободен |
| Target / Dest | `/run/x-ui-selfsteal/https.sock` |
| Xver / PROXY protocol | `1` |
| Server Names | Только собственный `edge.example.com` из окружения |
| Reality keypair | Создать новую пару средствами панели |
| Short ID | Создать непустой случайный ID средствами панели |
| Клиент | Новый тестовый UUID; для совместимого TCP-клиента можно использовать Vision |

Не вставляйте чужие ключи из примеров, не публикуйте private key, UUID и ссылки
подписки. Сохраните входящий и проверьте журнал Xray. Для Unix-target с PROXY v1
нужна совместимая версия ядра; служба заглушки сама эту совместимость не доказывает.

## 5. Host / узел подписки

| Поле | Значение |
|---|---|
| Привязка | Только новый тестовый входящий |
| Адрес | Ваш `edge.example.com` |
| Порт | Реальный порт нового входящего, а не автоматически 443 |
| Security | REALITY |
| SNI | Тот же `edge.example.com` |
| Fingerprint | `chrome` при поддержке клиентом |
| Path / Host header | Пусто для TCP/RAW |
| Переопределять SNI адресом | Выключено; SNI задан явно |
| Allow insecure | Выключено |

У разных версий панели разное расположение Hosts. Подписка не настраивает
маршрутизацию и не проверяет работоспособность узла: сперва протестируйте ручной
профиль на одном клиенте, затем включайте Host в общей подписке.

## 6. Совместная работа с HTTPS-транспортами

Переносить **все** входящие на 443 не требуется. Новый REALITY-фронтенд может
слушать свободный тестовый порт P. Тогда механизм выглядит так:

```text
узел:P → REALITY → авторизованный REALITY-клиент
                → локальный Nginx (обычный TLS, без REALITY-авторизации)
                    /             → сайт
                    /socket       → выбранный локальный WS backend
                    /upload/      → выбранный локальный XHTTP backend
                    /service/     → выбранный локальный gRPC backend
```

### Явный выбор backend

1. Используйте **отдельные тестовые** HTTP-входящие. Поддерживаются VLESS/VMess/Trojan
   с WS, HTTPUpgrade, XHTTP/SplitHTTP или gRPC; каждый backend должен быть включён,
   слушать `127.0.0.1` либо `::1` и иметь `security=none`. Это обычное локальное
   соединение за TLS-терминацией Nginx. Не отключайте TLS у рабочего входящего
   ради эксперимента: создайте отдельный тестовый при необходимости.
2. Задайте различные некорневые пути, например `/socket`, `/upload/`; для gRPC
   задайте отдельный serviceName, например `service`. Пустые/корневые пути,
   специальные символы, совпадающие и перекрывающиеся префиксы отклоняются.
   Query-параметры WS/XHTTP не включаются в nginx location, но исходный запрос с
   ними передаётся backend без подмены URI. Необходимые клиентские настройки
   транспорта остаются ответственностью администратора. Backend получает Host
   выбранного сайта без порта; если в его настройках задано обязательное имя Host,
   оно должно соответствовать этому домену. Другие имена автоматически не подменяются.
3. В серверном окружении **явно** перечислите ID этих backend:

   ```dotenv
   # Демонстрационные ID: замените на ID своих тестовых входящих.
   XUI_SELFSTEAL_PROXY_INBOUNDS=101,102,103
   XUI_DB_PATH=/etc/x-ui/x-ui.db
   ```

   Пустой/отсутствующий список означает **не проксировать ничего**. Для выбранных
   маршрутов нужен Python 3 со стандартным SQLite-модулем. Помощник
   `decoy/reality_routes.py` открывает существующую БД с `mode=ro` и
   `PRAGMA query_only=ON`, читает только выбранные входящие в одном snapshot.
   Новая БД не создаётся; SQL UPDATE/INSERT и изменение Hosts не выполняются.
   Неизвестный/выключенный ID, публичный listen, TLS/REALITY-backend, петля на
   порт заглушки или конфликт пути останавливают проверку **до замены Nginx**.
4. Запустите `x-ui-fork selfsteal plan`: проверьте показанные ID, пути и
   локальные адреса. Затем `x-ui-fork selfsteal apply` и `status`. Сам статус
   проверяет HTTPS-сайт через сокет, но не подтверждает работу всех backend.

### Поля Host для HTTP-транспорта

Не путайте с Host самого REALITY-входящего из раздела 5:

| Поле | Значение |
|---|---|
| Привязка | Соответствующий локальный WS/XHTTP/gRPC backend |
| Адрес | Собственный домен сайта, например `edge.example.com` |
| Внешний порт | P — фактический порт REALITY-фронтенда; не локальный порт backend |
| Security | **TLS**, а не REALITY и не none |
| SNI | Тот же собственный домен с доверенным сертификатом |
| Транспорт | Сохранить WS/HTTPUpgrade/XHTTP/gRPC |
| Path / serviceName | Должен совпадать с выбранным backend |
| ALPN | Для gRPC HTTP/2 (`h2`); HTTP/3/QUIC в этой схеме не поддерживается |
| Allow insecure | Выключено |

Сначала вручную проверьте профиль одного клиента, затем включайте Host в
подписке. Внутренний порт backend остаётся прежним; скрипт его не меняет.
Проверка/применение маршрутов не изменяет клиентские ссылки автоматически.

### Что остаётся отдельно

- Уже работающие TLS/REALITY-входящие сохраняют собственные настройки и порты.
  Нельзя добавить TLS-backend в этот список и ожидать автоматического снятия TLS.
- Обычный VLESS/TCP без HTTP не проксируется через nginx location; для его
  маскировки нужна отдельная подходящая схема, например fallback в Xray.
- Hysteria/UDP и MTProto остаются на своих портах; HTTP/3/UDP на TCP-фронтенд не
  переносится. Панель и подписки этим списком не публикуются.
- Этот режим обслуживает один явно заданный HTTPS-домен. Перенос старых
  виртуальных хостов с другими сертификатами автоматически не выполняется.

## 7. Приёмочные проверки и откат

- Реальный клиент подключается с новым профилем.
- Обычный браузер/HTTPS-клиент с правильным доменом и **без** реквизитов REALITY
  видит сайт с корректным сертификатом на порту входящего.
- `x-ui-fork selfsteal status` успешно проверяет Unix-сокет и сертификат.
- Если выбраны HTTP-маршруты: каждый реальный WS/XHTTP/gRPC-клиент работает через
  домен и порт фронтенда, а корень по-прежнему отдаёт сайт. Локальный тест
  HTTP-прокси не доказывает совместимость всех клиентов и версий Xray.
- Внешние старые профили и доступ к панели по-прежнему работают.
- Повторите тесты из разных сетей/операторов; локальный curl не доказывает
  устойчивость к конкретному ТСПУ. Отдельно проверьте DNS A/AAAA и IPv6-доступность.

Если тестовый входящий не работает, выключите его Host и сам входящий, оставьте
рабочие профили. **Перед возвратом** `XUI_SELFSTEAL_MODE=legacy` убедитесь, что ни
один активный входящий больше не использует Unix-сокет; отключение режима само
не возвращает изменённые вручную поля панели. Затем восстановите сохранённые
параметры публичности/HAProxy из своего окружения и примените decoy-настройки.

Заглушка не отменяет блокировку IP/диапазона, анализ потоков или ограничения
разрешённых адресов. Сравнивайте варианты измерениями, а не названием панели.

## Проверки разработки

```bash
bash -n decoy-setup.sh x-ui-fork.sh
sh -n init-config.sh
python3 -m unittest discover -s tests -v
```

Тесты создают временную CA и сертификат, проверяют ошибочные настройки, откат,
конфликты маршрутов, чтение SQLite/WAL без изменения данных. Отдельный Nginx
на временном сокете/непривилегированном порту одновременно отдаёт сайт,
проксирует HTTP POST с сохранением URI и передаёт WebSocket Upgrade с байтами
backend. gRPC проверяется на уровне генерации конфигурации, не полноценного
клиентского сеанса. Тесты не изменяют системные службы, `/etc`, активное
окружение или пользовательскую БД панели.
