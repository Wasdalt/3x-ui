# ACME, занятый порт 80 и восстановление БД

## Что исправлено

- Если публичный HTTP/80 обслуживает `x-ui-decoy.service`, Certbot использует
  webroot `/var/www/html`, который уже обслуживается legacy-заглушкой. Не нужно
  пытаться занять тот же порт вторым standalone-сервером. Выбранный webroot
  сохраняется Certbot для продления сертификата.
- Если порт принадлежит известному HAProxy, используется его ACME-backend 8088.
  Это не универсальный обход занятого 80: соответствующая маршрутизация HAProxy
  должна реально работать.
- Обычная веб-служба временно останавливается только когда её MainPID совпал с
  владельцем порта из `ss`. Восстанавливается только эта ранее активная служба,
  в том числе при неуспехе. Выключенный HAProxy не запускается "на всякий случай".
- Неизвестный владелец или несколько владельцев порта не уничтожаются и не
  останавливаются автоматически. Нужна ручная диагностика.
- Запросы из нескольких точек обвязки сериализуются через `flock`, если он
  доступен. После ошибки действует пауза 300 секунд для того же домена. Файлы
  `.certbot.lock` никогда не удаляются. Внешние запуски Certbot по-прежнему
  защищаются его собственной блокировкой.
- Неудачный выпуск не очищает сохранённый домен панели и пути сертификатов,
  не заменяет установленный TLS самоподписанным. При незавершённом переходе
  legacy-синхронизация сертификатов входящих и Hosts также пропускается.
- Сохранённые домен и TLS подписки не заменяются доменом панели только потому,
  что отдельный сертификат подписки не выпущен. Если сохранённые файлы TLS
  недоступны, подписка отключается до исправления, а не публикуется по HTTP.
  Явный режим `XUI_ALLOW_HTTP=true` остаётся отдельным осознанным выбором.

## Обновление сервера

Обновление обвязки может перезапускать панель и менять явно заданные параметры
окружения. Сохраните SSH-доступ и сделайте резервную копию БД и активного `.env`.
Не загружайте бэкап заново ради исправления ошибки Certbot.

В каталоге проекта **на сервере**, после публикации исправленного коммита:

```bash
git pull --ff-only
x-ui-fork backup
x-ui-fork apply
```

Перед применением проверьте:

1. `XUI_DOMAIN`, `XUI_SUB_DOMAIN`, `XUI_SELFSTEAL_DOMAIN` содержат **публичные имена
   записей DNS**, а не имена целей CNAME. CNAME на сервер r1 не создаёт поддомен
   workspace.r1, если слева записано workspace.r2.
2. DNS A/AAAA/CNAME ведёт именно на нужный сервер. Две A-записи означают, что
   ACME-проверка может попасть на любой из двух серверов. Обслуживание challenge
   должно работать на каждом адресе либо нужно оставить один правильный адрес.
3. Нет других активных попыток Certbot:

   ```bash
   pgrep -af certbot
   systemctl status certbot.service certbot.timer --no-pager
   ss -ltnp '( sport = :80 )'
   ```

   Не удаляйте lock-файлы и не завершайте процессы вслепую. Дождитесь завершения
   текущей попытки. Для неизвестного владельца порта сначала установите его
   назначение и влияние остановки на работающие сервисы.
4. TCP/80 доступен извне для HTTP-01, иначе используйте отдельно настроенный
   DNS-01. Исправление локального конфликта не чинит firewall, NAT или DNS.

Для явного повторного запроса после исправления причины можно временно задать
в активном `.env` `XUI_CERTBOT_RETRY_DELAY=0`, применить один раз и затем вернуть
300 или удалить параметр. Не оставляйте 0 для бесконечного автоматического
повтора: это может привести к ограничениям CA. При активном запросе из другой
точки новый запрос пропускается, а не запускается параллельно.

## Что происходит с галочкой «сохранять URL/настройки» при импорте

Эту галочку обрабатывает сама установленная версия панели. После импорта
systemd-наблюдатель и предварительный шаг запуска применяют обвязку отдельно.
Пустые `XUI_PORT`/`XUI_BASE_PATH` означают «сохранить текущее значение БД», а не
«восстановить значение новой установки до загрузки бэкапа». Новые значения
генерируются только если соответствующее поле БД тоже пусто.

Исправление предотвращает последующее повреждение домена/TLS при ошибках ACME,
но **не восстанавливает уже утраченные значения**. Если старый порт/путь попал
в БД при импорте, нужны сохранённые значения новой установки либо осознанное
явное переопределение этих полей. Не публикуйте пароль, закрытый ключ,
непредсказуемый путь панели или ссылки подписки в диагностических сообщениях.

Для совершенно новой БД без сохранённых TLS-настроек прежний bootstrap с
самоподписанным сертификатом панели сохраняется; собственный домен при этом
не очищается. Доверенный сертификат всё равно необходимо выпустить отдельно.
