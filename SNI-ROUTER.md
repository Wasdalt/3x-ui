# Два профиля REALITY на одном внешнем TCP 443

Это **отдельный** явно включаемый L4-router, а не старый режим автомиграции
HAProxy. TLS не завершается в router; маршрутизация идёт по открытому SNI.
БД, порты, SNI и Hosts автоматически не переписываются.

**Списки в окружении вводить не обязательно.** Router находит готовые профили по
настройкам панели: включённый локальный REALITY-входящий и включённый Host на
внешнем443 с совпадающим SNI. Домены сайта читаются из serverNames входящих,
направленных на локальный SelfSteal. Ничего не переименовывается и не
перепривязывается по догадке. `plan` показывает найденную схему до запуска.

Пример для конкретного узла:

```text
внешний TCP443 → x-ui-sni-router.service (HAProxy)
    studio.r1.netstability.ru → №4  127.0.0.1:10443 → TCP/REALITY
    media.r1.netstability.ru  → №13 127.0.0.1:8443  → XHTTP/REALITY
    неизвестный SNI          → локальный HTTPS-сайт Nginx
```

Оба REALITY-входящих направляют неавторизованные TLS-подключения в локальный
Unix-сокет SelfSteal с `xver=1`. Router передаёт PROXY protocol v1 в Xray,
поэтому **у обоих входящих обязателен `sockopt.acceptProxyProtocol=true`**.
Router не выполняет TLS-терминацию и не заменяет ClientHello своим отпечатком.
Это не гарантия обхода фильтрации или блокировки IP.

## Условия

- Нативная установка с systemd, Xray/x-ui от root, `haproxy`, `python3`, Nginx.
- `XUI_SELFSTEAL_MODE=reality`, собственный сайт и его доверенный сертификат.
- Разные SNI у выбранных входящих; одинаковые SNI отклоняются, а не выбирается
  первый случайный backend. Не используйте различие ALPN как замену имени.
- Только подготовленные включённые VLESS/REALITY-входящие на loopback-портах
  с активными внешними Hosts на443 (или ограничение явным списком ID).
  Публичный listen, TCP443 как backend и петля на HTTPS-порт отклоняются.
- Старый `XUI_HAPROXY_ENABLE` остаётся **false**. Он управляет другой службой
  и несовместим с этим маршрутизатором. Не включайте две службы на одном443.
- Требуется **один основной сертификат SelfSteal с SAN всех используемых имён**.
  Автоматическая сборка нескольких случайных сертификатов здесь не применяется.

## 1. DNS и сертификат — до импорта БД

Оба публичных имени должны вести на нужный IP. Домены в этой инструкции —
пример конкретного развёртывания, а не значения по умолчанию форка.

Для studio + media расширьте сертификат с именем **studio**, сохранив его путь.
Если в нём уже есть другие нужные SAN, сохраните их в запросе тоже — не
заменяйте существующий набор имён вслепую только этими двумя.
Сначала убедитесь, что другие процессы Certbot не работают и HTTP/80 свободен
и доступен извне. Не останавливайте чужие службы вслепую.

```bash
pgrep -af certbot
ss -ltnp '( sport = :80 )'
certbot certonly --standalone --http-01-port 80 \
  --cert-name studio.r1.netstability.ru --expand \
  -d studio.r1.netstability.ru -d media.r1.netstability.ru
```

Не повторяйте запрос бесконечно при ошибке. Если standalone непригоден,
используйте заранее настроенный DNS-01/HTTP-01 своим ACME-клиентом.
Проверьте SAN, срок и цепочку. Одного сертификата только media недостаточно:
проверяется основной `XUI_SELFSTEAL_CERT_FILE` (по умолчанию путь studio).

## 2. Окружение и обновлённая обвязка

Сохраните рабочую БД, активное окружение и SSH-доступ. После публикации кода:

```bash
x-ui-fork backup
git pull --ff-only
```

Добавьте в серверный `.env`, сохраняя остальные рабочие параметры:

```dotenv
XUI_HAPROXY_ENABLE=false
XUI_SELFSTEAL_ENABLE=true
XUI_SELFSTEAL_MODE=reality
XUI_SELFSTEAL_PUBLIC=false
XUI_SNI_ROUTER_ENABLE=true
XUI_REWRITE_INBOUNDS=false
XUI_HOSTS_SYNC=false
XUI_AUTO_DB_APPLY=false
```

`XUI_SELFSTEAL_DOMAIN`, `XUI_SELFSTEAL_EXTRA_DOMAINS` и
`XUI_SNI_ROUTER_INBOUNDS` можно не задавать: подготовленная БД содержит studio,
media и связи Hosts. Если эти параметры уже есть в окружении, они остаются
явным переопределением/ограничением; уберите устаревшие значения, если хотите
использовать обнаружение из панели.

Если используете прежний XHTTP-backend №30, оставьте
`XUI_SELFSTEAL_PROXY_INBOUNDS=30`. Не добавляйте №13 в этот HTTP-список:
№13 имеет собственный REALITY и идёт через L4 SNI-router.

Общий `x-ui-fork apply` один раз установит обновлённые помощники и HTTPS-сайт
с обоими именами. Он **не запускает** новый router и не переносит входящие.
Это операция развёртывания с перезапуском панели; подготовьте окно работ.
Если дополнительный SAN не подходит, проверка остановится до подмены сайта.

## 3. Подготовленная БД

Перед запуском router входящие должны иметь:

| | №4 Финляндия | №13 Обход №2 |
|---|---|---|
| Listen / локальный порт | 127.0.0.1:10443 | 127.0.0.1:8443 |
| Транспорт | TCP/RAW | XHTTP |
| Защита | REALITY | REALITY |
| Server Names | studio.r1.netstability.ru | media.r1.netstability.ru |
| sockopt.acceptProxyProtocol | true | true |
| Reality target | /run/x-ui-selfsteal/https.sock | тот же |
| Reality xver | 1 | 1 |
| Flow | Существующий TCP/Vision | Пусто, Vision отключён только здесь |
| Host адрес / порт | studio.r1.netstability.ru:443 | media.r1.netstability.ru:443 |
| Host security / SNI | reality / studio.r1... | reality / media.r1... |
| XHTTP path | — | /api/v2/session/ |

Ключи каждого REALITY остаются собственными; их не надо объединять. Теги и
правила маршрутизации должны соответствовать внутренним входящим, не быть
случайно переназначены друг другу. Hysteria/UDP443 остаётся отдельной службой.

Загрузите подготовленный бэкап в совместимую версию панели и сохраните нужные
параметры URL панели опцией импортера. Дождитесь применения/перезапуска Xray.
После этого **до запуска router будет короткий перерыв во внешнем TCP443**.
Не пытайтесь проверить прямое подключение к backend без PROXY header:
они намеренно принимают только подключения через router.

## 4. Проверить и включить SNI-router

```bash
x-ui-fork selfsteal status
x-ui-fork sni-router plan
x-ui-fork sni-router apply
x-ui-fork sni-router status
ss -ltnp '( sport = :443 )'
```

`plan` читает БД без записи, проверяет имена/порты, покрытие SAN и синтаксис
конфига HAProxy. `apply` дополнительно проверяет реальный локальный TLS fallback
каждого Xray backend с PROXY header. Занятый чужим процессом443 не освобождается
автоматически. Конфигурация меняется только после проверок; при ошибке запуска
предыдущие файлы/служба router восстанавливаются.

На внешнем TCP443 теперь ожидается **HAProxy управляемой службы
x-ui-sni-router.service**, а не Xray. Xray слушает два loopback-порта.
Это нормально и отличается от прежней прямой схемы.

Обновите оба профиля/подписку и проверьте настоящее подключение, выходной
маршрут и браузерный HTTPS-ответ для каждого имени. Успешная локальная проверка
не доказывает совместимость всех клиентов, транспорта и сетей провайдеров.

## Откат

```bash
x-ui-fork sni-router stop
```

Останавливается только управляемый router; БД не откатывается автоматически.
Верните сохранённые рабочую БД и окружение, затем штатно примените настройки
панели. Сначала остановите router, прежде чем возвращать Xray на публичный443,
иначе снова возникнет bind conflict. Не удаляйте нужный дополнительный SAN
из рабочего сертификата при продлении.
